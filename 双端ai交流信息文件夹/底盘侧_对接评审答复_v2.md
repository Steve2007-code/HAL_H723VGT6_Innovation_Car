## 2. 对回信 §4 三个问题的明确回答

### Q1 — 是否接受「通用成帧层 + 两个实例」？

**接受，无保留。**

- 板间 `Y / E / A / S / C / K` 帧统一由 `parse_cmd_ints()` 解析，字段数 2~5 都支持；
- `parse_i()` 从 `vision.c` 抽出共用；`vision.c` 持有 `s_cam`，`mcu_link.c` 持有 `s_link`；
- 摄像头帧 `<<X,dx,Y,dy>>` 格式**不变**，避免动已验证的视觉链路语义；
- 底盘侧 H723 用独立 `FrameRx_t` 等价实现（`s_link_h723`），**不复用** `Debug.c` 的命令行解析器，理由见 §1 末。

### Q2 — `<<Y,pos,vel>>` 的 `pos` 由谁算、依据什么算？与 A 轴 PID 如何分工？

**底盘侧立场（明确、不需要再协商）：**

> `Y.pos` **完全由 F103 侧产生**。底盘 H723 **不读视觉、不算误差、不参与任何闭环**，
> 只做三件事：**硬限幅 → 转发 CAN 帧 `0x105` → 把 4340 实际回传角度上报给 F103**。
> `Y` 的语义是「**绝对位置(rad) + 限速(rad/s)**」，位置环在 4340 驱动器内部闭合，不是增量、不是速度指令。

**这直接回答了「两个执行器抢同一个误差」的风险**：底盘侧不是执行器之一，它只是 CAN 通道；
真正需要分工的是 **F103 内部「yaw 目标」与「A 轴视觉 PID」**，这一项底盘侧不替用户决定，只给建议：

| 方案 | 做法 | 评价 |
|---|---|---|
| **① 离散工位角（本期推荐）** | yaw 目标**不由视觉算**，由 F103 上层任务 / 上位机给离散目标角（例如各取放工位对应的固定角度）；A 轴继续用视觉 `dx` 做水平精调 | 两者**误差源不同，天然不打架**；实现量最小，本期建议 |
| ② 视觉粗调 + A 轴精调 | yaw 用视觉 `dx` 做粗调（大死区、低 Kp、限幅），A 轴做精调 | 必须给 yaw **独立的符号 / Kp / 死区 / 限幅**，不得复用 `TRACK_SIGN` / `TRACK_KP` / `TRACK_DEAD_PX`；还要定义优先级。本期不建议 |

**需用户定义的只有一句**：yaw 目标到底来自「离散工位角 / 视觉粗调 / 上位机下发」三选一。
无论选哪个，底盘侧接口不变（都是 `Y.pos_mrad`）。**不允许**出现「A 轴 PID 和 yaw 同时吃同一个 `dx` 且无分工」的状态。

### Q3 — 「收命令」到底是谁收？

**选 (a)：F103 本期只发命令，不接收来自 H723 的命令帧。**

- 机械臂侧**把 `g_track_enabled` 从计划中去掉**；
- H723 → F103 **本期只发状态 / 确认帧** `A` / `K`（`C` 可选、本期不启用），**不设** `<<G,posA>>` / `<<M,0|1>>` 之类命令帧；
- 用户当时选的「双向」，本期的准确含义是：**F103 发命令 + 两边都能发状态**，不是「H723 给机械臂下命令」；
- 留口：将来若需要「底盘到位 → 通知机械臂开始取料」这类任务协同，再单独新增 `C` 帧或命令帧，**不在本期范围**，避免范围蔓延。

## 3. 两侧拟对齐的技术细节（底盘侧收敛稿，待机械臂侧确认）

### 3.1 物理层（**本版已修订：USART6 → UART7**）

| 项 | 决定 |
|---|---|
| 链路 | **F103 USART2 (PA2/PA3) ↔ H723 UART7**（用户指定） |
| H723 UART7 引脚 | **由用户按原理图 / 丝印自行确定**，AI 不指定、不配置 |
| UART7 外设配置 | **用户自行完成**：GPIO / AF、时钟、NVIC 优先级、`huart7` 句柄、`UART7_IRQHandler`、非阻塞收发。两个 AI 均不碰 |
| 必须避开的已占用引脚 | H723 **USART1 PA9/PA10（调试口）**、**PC15（外部 VCC 供电控制）**、FDCAN1 PD0/PD1、FDCAN3 PD12/PD13、SPI6 PA5/PA7 |
| 电平 / 速率 | 3.3V TTL，**必须共地**，TX↔RX 交叉；115200 8N1；不是 RS232/RS485 |
| F103 侧坑 | `BRR = (SystemCoreClock/2)/115200 = 312`（**不是 625**）；USART2 时钟在 **`RCC->APB1ENR`**；`IOPAEN` 幂等再置；**别动 `AFIO->MAPR` 的 USART2 重映射位** |
| 中断优先级 | F103：TIM2=1 > TIM3=2 > USART1=3 > **USART2=4**；H723：**UART7 RX 中断必须低于 TIM4**（200Hz 控制环最高） |

> ⚠ **v1 §1 / §6-1 与初版 v2 中「推荐 USART6 PC6/PC7、复用 `UART_Data.c` 注释模板」的推理全部作废**，
> 以用户指定的 **UART7** 为准。机械臂侧 §2.11 已明确「H723 选哪个口不影响 F103 任何代码」，
> 所以此变更**对 F103 侧零影响**，仅需你侧在回信里确认知悉。

#### 3.1.1 用户自行配置 UART7 时的对接约定（给 AI 写协议层用）

用户配好 UART7 后，底盘侧 AI 只写 `Link.c/.h` **协议层**，按用户提供的接口适配。需要的最小约定：

| # | 约定 | 理由 |
|---|---|---|
| 1 | RX 中断**只把字节喂给 Link 层**（`Link_FeedByte(c)` 或写入独立 RX FIFO），**不做组包 / 解析 / 协议栈** | 与 §2.7 一致，避免 ISR 里跑协议栈 |
| 2 | 发送走 TXE / `HAL_UART_Transmit_IT` + 环形缓冲，**禁止忙等**；Link 层需能拿到 `huart7`（`extern` 句柄或用户提供的 `Link_SendBytes()` 钩子，形式由用户定） | 不破坏 H723 的 200Hz 控制环 |
| 3 | 帧内不放换行、不加校验和，纯 `<<...>>` | 见 §3.2 |
| 4 | 115200 8N1、3.3V TTL、共地、TX↔RX 交叉、UART7 中断优先级低于 TIM4 | 物理层一致 |
| 5 | `UART7_IRQHandler` 由用户实现；AI **不改**该 ISR 的外设部分，只在其中挂一个字节喂入口 | 职责边界，见 §7 |

> 具体句柄名 / FIFO 名 / 钩子形式**由用户配置时定**，AI 按实适配；**AI 不修改 UART7 的 CubeMX / 时钟 / GPIO / NVIC 配置**。

### 3.2 成帧层（双方一致）

- 包头 `<<`、包尾 `>>`，逗号分隔，纯 ASCII 文本，**帧内不放换行**；`\r\n` 只允许出现在包尾之后（当噪声丢弃）
- **不加校验和**（沿用用户决定）；靠包头包尾 + 状态机做粘包 / 半包 / 噪声 / 重复包头容错
- `FrameRx_t` 通用成帧层，`Frame_FeedByte()` 只在中断里喂字节，`Frame_Poll()` 在主循环取 body
- **两个实例**：`s_cam`（USART1 摄像头）/ `s_link`（USART2 板间）；H723 侧另有一个独立实例
- 数值解析统一 `parse_i()` + `parse_cmd_ints()`，支持 2~5 字段、有符号整数

### 3.4 限幅与控制语义（H723 侧硬钳，防 F103 发飞）

| 项 | 值 |
|---|---|
| `Y.pos` 限幅 | `[-3142, +3142]`（±π，可按 yaw 机械限位再收紧） |
| `Y.vel` 限幅 | `[-3000, +3000]`（±3 rad/s，远小于 4340 的 ±30） |
| 超限时 | 以**钳位值**下发，并回一次 `<<K,4>>`，不丢帧、不静默 |
| CAN 帧 | `DM_CAN_Motor_Position_Speed(&DM_Motor_4340P_Yaw_StructData, vel, pos)` → `0x100+0x05 = 0x105`，8B，小端 `float pos + float vel` |
| 限流 | `0x105` 下发 **≤100 Hz**，与 FDCAN1 上 4×4310 的 200Hz `0x201~0x204` 共存（1Mbps，总占用约 10%） |

### 3.5 时序与握手

```
F103  上电 → Link_Init()（USART2, BRR=312）→ 默认不发 Y
      │
      ├─ 发 <<E,1>> ──────────────────────────USART2──► H723（UART7，用户已配好）
      │                                                  │ Link_Poll()（主循环，与 Debug_Task 并列）
      │                                                  ├─ DM_CAN_Motor_SetEnable(0x05, Enable)
      │                                                  └─ 回 <<K,2>>
      │
      ├─ 100Hz <<Y,pos,vel>> ──────────────────USART2──► H723 UART7 RX 中断：仅喂字节进 FIFO
      │                                                  │ Link_Poll()：Frame_Poll → parse_cmd_ints → 限幅 → 看门狗
      │                                                  │ 主循环非阻塞代发 DM_CAN_Motor_Position_Speed() → CAN 0x105
      │                                                  │        （CAN 发送绝不放在串口 RX 中断里）
      │                                                  │
      │  ◄────── 10~20Hz <<A,pos,vel,err>> ──────────────┤ 4340 回传 0x15 → Motor_UpdateData 已补 case
      │                                                  │
      └─ Track_Update() PID 在主循环 10ms 任务，不被串口阻塞
```

**三条硬约束（双方共同遵守）**：
1. **ISR 只收字节 / 只置标志**，不做组包、不做解析、不做协议栈；发送走 TXE / `HAL_UART_Transmit_IT` + 环形缓冲，**禁止忙等**
2. **CAN 代发放主循环**，不进串口 RX 中断；H723 的 `Link_Poll()` 不进 TIM4 5ms 中断
3. **控制权单一**：yaw 只由 F103 经板间串口控制；H723 调试口**不另开** yaw 命令（本地点动若需要，另设互斥标志，待拍板）

### 3.6 超时与安全

| 机制 | 决定 |
|---|---|
| 上电默认 | yaw **失能**；收到 `<<E,1>>` + 首帧 `Y` 才开始下发 `0x105`（⚠ 与现状冲突，见 §4.2） |
| H723 yaw 看门狗 | **400 ms** 无 `Y` → 停止下发 `0x105`，**保持当前位置**（不是失能），置故障标志，回一次 `<<K,5>>` |
| 恢复 | 重新收到 `Y` 即恢复下发，无需重发 `E`；但 `E 0` 之后必须 `E 1` 才能恢复 |
| `E 0` | `DM_CAN_Motor_SetEnable(0x05, Disable)` + 停止下发 |
| F103 对称断链 | >1 s 收不到 `A`/`K` → 置 `link_lost` 标志 + `Y` 降频 / 停发；**绝不阻塞 `Track_Update()` 的 PID** |
| 断链动作选「保持位置」而非「失能」 | 采纳机械臂侧 §5-7：失能会让 yaw 自由下垂 / 被反拖，不安全 |

### 3.7 带宽（沿用机械臂侧 §2.9 核算）

| 帧 | 长度 | 频率 | 占用 |
|---|---:|---:|---:|
| `<<Y,...>>` | ~15 B | 100 Hz | ~1500 B/s |
| `<<S,...>>` | ~25 B | 20 Hz | ~500 B/s |
| `<<A,...>>` / `<<K,...>>` | ~20 B | 合计 ~20 Hz | ~400 B/s |

115200 8N1 ≈ 11520 B/s，总计 **< 25%**。文本帧可放心用，**不加校验和**；现场干扰大再考虑补 1 字节 XOR，先不加。

### 4.2 🚨 第 4 卡点：上电流程默认把 yaw 4340 **使能**了，与「上电失能」约定冲突

`Core/Src/main.c` 上电流程实测：


协议 §3.6 要求「上电默认 yaw 失能，直到 `E 1` + 首帧 `Y`」。两者冲突。
4340 是位置速度模式，使能后不发 `0x105` 理论上会锁当前角，但**严格不满足约定**，且上电瞬间存在风险。

**两个处置，请你拍板**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（底盘侧倾向）** | 删掉 165 行的 yaw 使能，改由 `<<E,1>>` 触发 Enable、`<<E,0>>` 触发 Disable | 完全符合约定，改动 1 行 + Link 层 2 处调用 |
| B | 保留上电 Enable，但 Link 层在收到 `E 1` + 首帧 `Y` 前**一条 `0x105` 都不发**（软件门控代替电气失能） | 改动更小，但严格说不算「失能」；请按 yaw 机械结构判断能否接受 |

> 注意：这与 §3.6「断链保持位置而非失能」**不矛盾** —— 上电失能、运行中断链保持，是两种不同状态。

### 4.3 佐证：USART1 绝不能拿来当板间链路

`HAL_UART_RxCpltCallback()` 的 USART1 分支里有一段遗留彩灯测试代码：

```c
if(UART1_RX_Buf[0] == 'G')       WS2812_SetColor_DMA(255,0,0);
else if(UART1_RX_Buf[0] == 'R')  WS2812_SetColor_DMA(0,255,0);
else if(UART1_RX_Buf[0] == 'B')  WS2812_SetColor_DMA(0,0,255);
```

调试口同时承载 `printf` 遥测和命令行，**若板间帧走 USART1，帧里的 `G/R/B` 字符会误触发 WS2812，且 printf 会污染链路**。
这从源码层面再次确认：**必须另开一路独立串口（用户已定 UART7）**，也回应了机械臂侧 §2.11「别把调试口 USART1 混进来」的提醒。
（本期底盘侧**不动**这段遗留代码，它不影响 UART7。）

### 4.4 `0x15` 回传解析复用 `DM_IMU_Update4310P()`，格式一致但量程要分清

`Motor_UpdateData()` 新补的 case 实测：

```c
case DM_Motor_4340_Yaw_BackID:
    memcpy(DM_Motor_4340P_Yaw_StructData.UpData, pData, 8);
    DM_IMU_Update4310P(&DM_Motor_4340P_Yaw_StructData);
    break;
```

达妙 4310/4340 的 8B 回传格式一致（统一 MIT 回传：`[0]=ID/ERR, [1:2]=POS 16bit, [3:4]=VEL 12bit + T 高4位, ...`），复用解析函数合理，函数名带 `4310` 只是历史命名。
但要注意：`DM_Raw_To_Value()` 用的是结构体的 **`Position_max/min = ±12 rad`**，所以 `A` 帧回传的 pos 是**量程 ±12 rad 的绝对位置**，
**不要**拿它和 `Y` 帧的 `±π`（±3.142）限幅混为一谈，也不要把 `A.pos` 直接回灌成 `Y.pos`。
