## 1. 你要求的两个确认项（底盘侧实测答复）

### 1.1 `A` 帧是否无条件 20Hz 持续发（即使 yaw 未使能）？

**是，无条件。** `MDK-ARM/USER/src/Link.c:330~333`：

```c
    /* 4) A 帧 20Hz 上报 */
    if (now - s_last_a_ms >= LINK_A_PERIOD_MS)   /* LINK_A_PERIOD_MS = 50 */
    {
        s_last_a_ms = now;
        s_send_a();
    }
```

该分支**不看** `s_yaw_enabled`、不看 `s_link_lost`、不看是否收到过 `Y`。
`Link_Init()` 里 `s_last_a_ms = 0`，配合 `Link_Poll()` 的 `s_first_poll` 首帧对齐，上电进入主循环后**第一帧 A 立即发出**，之后固定 20Hz。

- 未使能 / 断链期间 `A` 帧里的 `POS`/`VEL`/`err` 取自 `DM_Motor_4340P_Yaw_StructData`（4340 回传 `0x15` 填的结构体）；若电机失能时无回传，字段可能是 0 或上次残留值。**不影响链路活性判断**，本期 F103 只存不解释、yaw 目标用编译期默认值，无影响。
- 这正是你问的「影响误判断链时的表现」：**只要 H723→F103 物理链路通，F103 就会持续收到 `A`，`link_lost` 不会误置位**；H723 侧 400ms 看门狗只看 `Y`，与 `A` 无关。

> ⚠ **但这恰恰是 §2 竞态的根源**，见下节。

### 1.2 UART7 分支是否按句柄判断、会不会落到 USART1 彩灯逻辑？

**按句柄判断，且 `return` 提前返回，不会落到 USART1 分支。** `UART_Data.c:82~89`：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
	if(huart->Instance == UART7)              /* 按句柄判断 */
    {
        Link_FeedByte(UART7_RX_Buf[0]);       /* 只喂字节, 不做解析 */
        HAL_UART_Receive_IT(&huart7, UART7_RX_Buf, 1);
        return;                               /* 关键: 提前返回 */
    }
	/* ... 以下才是 USART1 分支, 含 G/R/B -> WS2812_SetColor_DMA ... */
```

- 后面的 USART1 分支本身也是 `if(huart->Instance == USART1)`，**句柄互斥 + `return` 双保险**；
- USART1 的 FIFO 逻辑与 `WS2812_SetColor_DMA()` 彩灯代码**一行未动**；
- `HAL_UART_ErrorCallback()` 的 UART7 分支（`UART_Data.c:133~134`）没有 `return`，但后面同样是 `if (huart->Instance == USART1)`，句柄互斥不会命中；**不构成风险**。若你希望绝对对称，可在该分支也加一句 `return`，但那属于锦上添花，底盘侧不擅自改。

## 2. 🚨 修法复核：边界问题成立，但「1 行」有竞态

### 2.1 先修正你 §2.1 第 3 步的时序

你写的是「H723 上电发 `K,1` → 400ms 无 `Y` 回 `K,5` → F103 收到 `K,5` 刷新活性 → 恢复发 `Y`」。
按 §1.1 的事实，**实际更早**：H723 一进主循环就无条件 20Hz 发 `A`，F103 按 §2.5「收到任意 `A`/`K` 即清 `link_lost`」在 **≤50ms** 内就恢复发 `Y`，根本等不到 400ms 的 `K,5`；H723 收到 `Y` 后也会清自己的 `s_link_lost`，所以 `K,5` 很可能**根本不会发**。

结果与你一致（链路看着活着、`Y`/`A` 都有，yaw 不动），但**恢复路径不同**——而这一步差异正好决定修法是否可靠。

### 2.2 竞态推演

你 §2.2 的修法：

```c
if ((elapsed < LINK_E_RETRY_SPAN_MS || s_link_lost) &&
    (now - s_last_e_ms) >= LINK_E_RETRY_MS) {
    s_last_e_ms = now;
    send_frame("<<E,1>>");
}
```

`E,1` 补发的停止条件是「`elapsed >= 1000` **且** `s_link_lost == 0`」。而 `s_link_lost` 会被 `A` 帧在 H723 上电后 ≤50ms 内清掉，于是：

| 时刻 | F103 | H723 |
|---|---|---|
| t < T（H723 未起） | `link_lost=1`，每 100ms 补发 `E,1`（全丢） | 未上电 |
| t = T | 仍 `link_lost=1` | 上电，发 `K,1` + **第一帧 `A`** |
| t = T + δ（δ ≤ 50ms） | 收到 `A` → **`link_lost=0` → 补发 `E,1` 立即停止**；恢复 100Hz `Y` | 尚未收到任何 `E,1`（`s_yaw_enabled=0`） |
| t > T + δ | 正常发 `Y`，但**不再发 `E,1`**（`elapsed>=1000` 且 `link_lost=0`） | 收到 `Y` 只刷看门狗、不转发 `0x105`，且不回 `K,2` |

F103 在 `[T, T+δ]` 窗口内是否恰好发出过一帧 `E,1`，取决于 `s_last_e_ms` 相对于 T 的相位（`E,1` 周期 100ms，窗口 ≤50ms）——**约有一半概率没发出去**。此时 H723 永远失能，yaw 依旧不动，且因为 `A`/`Y` 都在，F103 不会有任何异常提示。

> 反直觉的一点：如果 F103 是靠 400ms 后的 `K,5` 恢复（你原推演），断链期间会补发约 4 次 `E,1`，修法 100% 可靠；
> **恰恰是「A 帧无条件 20Hz」把唤醒提前，让「只在 link_lost 期间补发」变得不可靠。**

### 2.3 建议的加强修法（机械臂侧，底盘侧零改动，不动协议/帧集）

把「`E,1` 补发」的停止条件从「时间窗 / 断链状态」改成**「H723 是否已确认使能」**——用现成的 `<<K,2>>` 作显式确认：

```c
/* 新增一个标志: 收到 K,2 置 1; 发 E,0 时清 0 */
static uint8_t s_yaw_ack = 0;

/* Link_TxTick() 里替换原补发条件 */
if (!s_yaw_ack && (now - s_last_e_ms) >= LINK_E_RETRY_MS) {
    s_last_e_ms = now;
    send_frame("<<E,1>>");
}
```

自愈链（100% 可靠，与任何时序无关）：

- 正常同时上电：H723 收到 `E,1` → 回 `K,2` → F103 置 `s_yaw_ack=1` → 补发停止（比原来更早停，更省）；
- **H723 晚起 >1s**：F103 一直没收到 `K,2` → 一直每 100ms 补发 `E,1` → H723 一起来必收到 → `DM_CAN_Motor_SetEnable()` + 回 `K,2` → F103 停止补发、恢复 `Y` → H723 转发 `0x105` → yaw 动；
- 底盘侧 `E,1` **幂等**（已使能不重复 Enable、不重复回 `K,2`），重复补发完全无害；
- 若将来发 `E,0`，清 `s_yaw_ack` 即可重新触发补发。

**这不违背定稿 §2.4「F103 不等 `K,2`」**：`K,2` 只是**后台低频补发（100ms 一帧）的停止信号**，F103 发 `E,1` 后**不等待、不阻塞**，100Hz `Y` 照常发，没有任何 ACK 状态机。§2.4 保留不变。

**改动量**：机械臂侧 `mcu_link.c` 三处（加标志、`K,2` 处置位、改补发条件）+ 可选在 25 场景里新增「H723 晚起 >1s，且 `A` 帧先于 `E,1` 到达 F103」这一竞态场景；**不动协议、不动帧定义、底盘侧零改动**。

> 备选（更小改动但依赖时序）：在 `link_lost` 由 1→0 的那个 tick 无条件补发一次 `<<E,1>>`。能覆盖竞态，但依赖 `Link_PollRx()` 与 `Link_TxTick()` 的先后顺序；不如 `s_yaw_ack` 稳，不推荐。
>
> 另有一条**底盘侧**思路（不推荐）：H723 在 `s_yaw_enabled == 0` 时不发 `A` 帧，让 F103 保持 `link_lost` 从而持续补发。但这改变了「A 帧无条件 20Hz」的既定行为、等于把活性信号 gate 掉，且要动底盘侧代码 + 重编译，破坏「底盘侧零改动」的干净分工，故不采用。
