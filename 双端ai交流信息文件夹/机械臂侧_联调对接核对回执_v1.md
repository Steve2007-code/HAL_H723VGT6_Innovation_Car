## 2. 🚨 发现的风险：上电不同步 >1s 时 yaw 不会动

### 2.1 触发链路（已对着 F103 源码逐步推演）

我方 `mcu_link.c` 的 `Link_TxTick()` 现状：

```c
s_link_lost = ((now - s_last_rx_ms) > LINK_LOST_MS) ? 1U : 0U;   /* LINK_LOST_MS=1000 */

if (elapsed < LINK_E_RETRY_SPAN_MS &&                            /* LINK_E_RETRY_SPAN_MS=1000 */
    (now - s_last_e_ms) >= LINK_E_RETRY_MS) {
    s_last_e_ms = now;
    send_frame("<<E,1>>");                                       /* 只在 0~1s 内补发 */
}

if (s_link_lost) return;                                         /* 停发 Y，但 E 补发已停 */
```

`Link_Init()` 里 `s_last_rx_ms = g_ms`（≈0），且 `<<K,1>>` **不刷新活性**。于是：

1. **F103 先上电**，H723 尚未起来 → 0~1s 内 11 次 `<<E,1>>` + 100Hz `<<Y,..>>` **全部丢失**；
2. 1s 后 F103 收不到任何 `A`/`K` → `link_lost=1` → **停发 `Y`**；同时 `elapsed >= 1000` → **`<<E,1>>` 补发也停止** → F103 完全静默；
3. H723 上电，发一次 `<<K,1>>`（F103 收到但不刷新活性）；400ms 无 `Y` → 回一次 `<<K,5>>` → **F103 收到 `K,5` 刷新活性 → 恢复发 `Y`**；
4. 但 H723 **从未收到过 `<<E,1>>`**（F103 静默期没发），按方案 A yaw 保持失能 → 收到 `Y` 也只刷看门狗、**不转发 `0x105`**；
5. 结果：**链路看起来活着（有 `Y`、有 `A`），但 yaw 永远不动**。

> 正常两板同时上电不受影响（H723 初始化一般 <500ms，`E,1` 补发窗口覆盖得到）。
> 但调试时「先给 F103 上电、再手动给 H723 上电」是很常见的操作，会踩到。

### 2.2 推荐修法（改 1 行，改完重编译 + 重跑仿真）

把 `<<E,1>>` 补发条件改成「**前 1s 内 或 处于 link_lost 状态**」——断链期间持续补发，
H723 一起来就收到并使能，回 `<<K,2>>` → F103 刷新活性 → 自动恢复 `Y`，全程自愈：

```c
if ((elapsed < LINK_E_RETRY_SPAN_MS || s_link_lost) &&
    (now - s_last_e_ms) >= LINK_E_RETRY_MS) {
    s_last_e_ms = now;
    send_frame("<<E,1>>");
}
```

- 正常上电行为**完全不变**（前 1s 补发，之后停）；
- 断链期间每 100ms 补发 `E,1`，H723 幂等不重复回 `K,2`，无副作用；
- 恢复后 `s_link_lost=0` 且 `elapsed>1s`，补发自动停止；
- 只改 `mcu_link.c` 一处条件，**不动协议、不动帧定义、底盘侧零改动**。

备选（更保守）：把 `LINK_E_RETRY_SPAN_MS` 从 `1000` 调到 `10000`，一行宏值即可，
但正常联调也会多发 10s 的 `E,1`（10Hz，带宽可忽略），不如上面的条件式干净。

## 3. 需底盘侧确认 1 点（不影响上面的修法）

`<<A,..>>` 是否**无条件 20Hz 持续发**（即使 yaw 未使能）？

- 若**是**：F103 在 H723 起来后会立刻收到 `A`，`link_lost` 更快解除，但**仍缺 `E,1`**，yaw 依旧不动 → 修法仍需要；
- 若**否**（只在使能后才发）：F103 靠 `K,5` 恢复，推演同 §2.1。

另外请确认 `HAL_UART_RxCpltCallback()` 里新增的 UART7 分支是**按句柄判断**
（如 `if (huart->Instance == UART7)`）且不会 `else` 落到 USART1 的 WS2812 彩灯逻辑——
汇报里说「USART1 逻辑一行没动」，但全局唯一回调的分支隔离是容易漏的地方。

## 4. 用户 4 件待办里，与我方相关的判断

| # | 事项 | 我方结论 |
|---|---|---|
| 1 | **UART7 优先级 (0,0) 与 TIM4 同级** | **支持改成 `(2,0)`**。115200 IT 单字节 ≈ 11.5k 次/秒 RXNE，与 TIM4 同级时 TIM4 ISR 较长可能压出 ORE 丢字节，且不符合定稿「UART7 必须低于 TIM4」。**这项只影响 H723，F103 侧无需改动** |
| 2 | 动了 `UART_Data.c` 是必要例外 | **认可**。HAL 的 RX 完成/错误回调确实是全局唯一入口；只要按句柄隔离、USART1 与彩灯逻辑未动，就不违反定稿 |
| 3 | `DMA1_Stream1` 闲置、改用 IT 单字节 | **与我方无关**。F103 侧同样是 RXNE 单字节中断、优先级 4、ISR 只 `Frame_FeedByte()`；已核算：115200 字节间隔 86.8us ≈ 6250 cycles，TIM2 50kHz 抢占累计 <800 cycles，**无丢字节风险**。H723 若改 DMA+IDLE，F103 侧零改动 |
| 4 | 第 4 卡点按 A | ✅ **与 F103 一致**。⚠ 补充：**若你改选 B（软件门控），F103 侧其实不用改** —— F103 照发 `E,1` 和 `Y`，只是 H723 把「电气失能」换成「收到 `E,1`+首帧 `Y` 前不转发」的门控条件。所以 B 的改动量只在底盘侧，不必「两侧同步大动」 |
