## 2. 我方补充锁定的实现细节（两 AI 必须逐字一致，否则同步改代码必出偏差）

> 这一节是「对接清楚」的核心：协议文档只定义"发什么"，这里定义"怎么解析、什么时候调用、失败怎么办"。
> 底盘侧 AI 按同一语义实现 `Link.c/.h` 的等价成帧层即可，**不需要复用我方源文件**。
> ⚠️ 本节全部条目为**机械臂侧新提出的补充约定**，底盘侧 AI 尚未确认，需转发后逐条复核。

### 2.1 `parse_cmd_ints()` 精确规范【最高优先级】

```
uint8_t parse_cmd_ints(const char *body, char *cmd, int32_t *vals, uint8_t max_vals);
```

- `body`：`Frame_Poll()` 产出、以 `\0` 结尾的字符串。
- 语法：`<CMD>,<V1>[,<V2>...]`。`<CMD>` **恰好 1 个 ASCII 字符**，本期白名单 `Y E A S C K`，
  未知 cmd 视为非法帧。
- `<Vi>`：可选单个 `+` 或 `-`，后接 1~10 位十进制数字；**不允许**空格、小数点、十六进制、空字段。
  用 `int32_t` 累加，**溢出视为非法**。`parse_i()` 从 `vision.c` 原样抽出，两边共用同一实现。
- 返回值：成功 = **值字段个数**（1~4）；失败 = `0`。
- 失败条件（任一即**丢弃整帧**）：body 为空 / cmd 非白名单 / 缺 `,` / 值字段 0 个 /
  值字段 > `max_vals` / 出现非法字符 / 末尾有多余字符 / 数值溢出。
- 失败处置：**H723 侧回一次 `<<K,3>>`**；**F103 侧只置 `rx_bad_frame` 标志，不回帧**。
- **纯函数、可重入、不得使用 static/全局变量** —— 主循环里 `s_cam`（X/Y 四字段专用解析）与
  `s_link`（本函数）会交替调用，共享静态状态会串。

示例：`"Y,1571,500"` → `cmd='Y'`, `vals={1571,500}`, 返回 2；`"E,1"` → 返回 1；
`"A,-1200,300,21"` → 返回 3；`"Y,,500"` → 返回 0（非法）。

### 2.2 `FrameRx_t` 成帧层行为与联调验收场景

```
void    Frame_FeedByte(FrameRx_t *q, uint8_t c);            /* 仅 RX 中断调用，只写环形缓冲 */
uint8_t Frame_Poll(FrameRx_t *q, char *out, uint8_t cap);   /* 仅主循环调用，1=取到一帧 */
```

- 状态机 `0=等<` / `1=等第二个<` / `2=收 body` / `3=等第二个>`，与 `vision.c` 现状一致。
- 容错（双方逐字一致）：
  - 重复包头 `<<<`：body 为空时多余的 `<` 忽略；
  - 粘包 `<<A,..>><<Y,..>>`：第二个 `>` 后若紧跟 `<`，直接进状态 1；
  - 超长：body 达 `cap-1` 仍未遇 `>` → 复位状态 0、丢帧；
  - 残缺包尾 / 噪声字节：状态 0/1 的非 `<` 字节丢弃，不复位卡死；
  - **帧内 `\r`/`\n` 会被当普通字符塞进 body → 解析失败**（双方都不发送行尾）。
- **三个实例互不共享状态**：`s_cam`(USART1)、`s_link`(USART2)、H723 侧 `s_link_h723`(UART7)。
  USART1 优先级 3 可嵌套 USART2 优先级 4，因实例独立而安全。
- 验收：我方重构 `vision.c` 后**重跑原 10 场景仿真**（正常/丢失/粘包/半包/噪声/残缺包尾/
  超长/重复包头/连续 100 帧/空帧恢复），并**新增板间帧场景**：`Y`/`E`/`A`/`K` 各 1、
  非法帧、超长、`<<<` 重复包头、粘包、缺字段、溢出 —— 全部 `ALL_PASS` 才算通过。

### 2.3 主循环 10ms 任务内执行顺序（锁死）

```c
while (1) {
    if (g_tick_10ms) {                 /* TIM3 ISR 只置此标志，绝不做协议栈 */
        g_tick_10ms = 0;

        Link_PollRx();                 /* 1) 先收：取干净 A / K，更新 link 状态与 link_lost */
        Track_Update();                /* 2) 视觉 PID：A 轴跟随，绝不阻塞、不发帧 */
        yaw_pos = Link_GetYawTarget(); /* 3) 取 yaw 目标（本期=接口默认值，待 §5-1 定） */
        Link_SendY(yaw_pos, yaw_vel);  /* 4) 只投递 TX 环形缓冲，非阻塞；TXE 中断发 */
    }
    /* LED / 其他非阻塞任务 */
}
```

要点：`Track_Update()` **不组包、不发送**；`Link_SendY()` **不等待发送完成**；
USART2 中断优先级 4，不会抢占 TIM2(1) / TIM3(2) / USART1(3)。
H723 侧 `Link_Poll()` 与 `Debug_Task()` 并列挂 `while(1)`，同样不在 TIM4 5ms 中断里。

### 2.4 握手：F103 不把 `K,2` 当发送前置条件（实现约束，不改帧定义）

F103 上电 → `Link_Init()` → 发 `<<E,1>>`（建议连发 2~3 次防上电不同步丢帧）→
**不等待 `<<K,2>>`**，直接按 100Hz 发 `Y`。`K,2` 收到只作状态记录。
理由：避免 F103 引入「等 ACK」状态机；H723 的 400ms 看门狗由 `Y` 刷新；`K,2` 丢失不影响功能。
**帧集、时序、字段一字未改，底盘侧无需改动**。

### 2.5 断链恢复条件（补锁）

- `link_lost` 置位：>1s 未收到任何 `A` 或 `K`。
- 置位后：**停发 `Y`**（H723 侧 400ms 看门狗已会保持当前位置，继续发无意义），
  `Track_Update()` 的视觉 PID **照常运行**，绝不阻塞。
- **恢复**：重新收到任意一帧 `A` 或 `K` → 立即清 `link_lost` → 恢复 100Hz `Y`，无需重发 `E`
  （但 `E 0` 之后必须 `E 1` 才能恢复，按 v2 §3.6）。

### 2.6 `K,1`（上电就绪）不参与链路判定

H723 上电主动发的 `<<K,1>>` 可能因 F103 未初始化完而丢失。F103 **不依赖 `K,1`**，
链路活性统一按 §2.5 的「任意 `A`/`K` + >1s 超时」判断。同样不改帧定义。

### 2.7 `A.err` 字段：F103 只存不解释

`<<A,pos_mrad,vel_mradps,err>>` 的 `err` 是达妙 MIT 回传的 `ID/ERR` 原始字节（0~255）。
F103 侧**只存进状态结构供调试查看，不做位解析、不触发动作**，避免两侧对错误码理解不一致。

### 2.9 量纲澄清：`Y` 与 `A` 同为 rad 绝对位置，但量程不同

- `Y.pos_mrad` = **目标绝对角**（rad ×1000），被协议层**人为安全限幅到 ±π（±3142）**；
- `4340` 结构体 `Position_max/min = ±12 rad`，`A.pos_mrad` 回报的是 **±12 rad 量程下的真实绝对角**；
- 两者**单位相同、可做误差**，但**不要把 `A.pos` 直接回灌成 `Y.pos`**（会把反馈当目标、自锁）；
- 若 yaw 机械限位允许超过 ±π，需**同步放宽 `Y` 限幅**，否则电机能力被协议白白砍掉；
- `Y.vel` ±3 rad/s 同样是协议层收紧（电机上限 ±30 rad/s），非电机限制。

### 2.11 F103 侧 USART2 裸机初始化检查表（我方自查用）

- `RCC->APB1ENR |= RCC_APB1ENR_USART2EN`（**APB1，不是 APB2**）
- `RCC->APB2ENR |= RCC_APB2ENR_IOPAEN | RCC_APB2ENR_AFIOEN`（**幂等再置，不依赖 `Vision_Init()` 顺序**）
- `GPIOA->CRL`：PA2 = `USART2_TX` 复用推挽 50MHz，PA3 = `USART2_RX` 浮空输入
- `USART2->BRR = (uint16_t)((SystemCoreClock / 2U) / 115200U) = 312`（**不是 625**）
- `USART2->CR1 = UE | RE | TE | RXNEIE | TXEIE`（TXEIE 按需在发送时开）
- `NVIC_SetPriority(USART2_IRQn, 4)`；**不动 `AFIO->MAPR` 的 USART2 重映射位**（PA2/PA3 与 `TIM2_CH3/4` 复用，但 TIM2 只做内部时基、不输出 PWM，不冲突）
- `USART2_IRQHandler`：RXNE 只 `Frame_FeedByte(&s_link, c)`；TXE 只从 TX 环形缓冲取字节写 `DR`，空则关 TXEIE

| **限幅** | H723 硬钳 `Y.pos ∈ [-3142,3142]`、`Y.vel ∈ [-3000,3000]`；超限按钳位值下发并回一次 `<<K,4>>`，不丢帧 |
| **CAN** | `DM_CAN_Motor_Position_Speed(&DM_Motor_4340P_Yaw_StructData, vel, pos)` → `0x105`，8B 小端 float；≤100Hz；**放主循环，不进串口 RX 中断**；与 4×4310 的 200Hz `0x201~0x204` 共存 |
| **回传** | 4340 `0x15` → `Motor_UpdateData()` 已补 case → 填 `A` 帧；`A.err` F103 只存不解释 |
| **时序** | F103 主循环 10ms 任务顺序见 §2.3；H723 `Link_Poll()` 挂 `while(1)` 与 `Debug_Task()` 并列；双方 ISR 只收字节/置标志；发送 TXE + 环形缓冲，**禁忙等** |
| **优先级** | F103：TIM2=1 > TIM3=2 > USART1=3 > USART2=4；H723：UART7 RX **低于 TIM4**（200Hz 环最高） |
| **握手** | 上电 yaw 失能 → F103 发 `E,1` → H723 Enable 并回 `K,2` → F103 100Hz `Y`（**不等 `K,2`**）→ H723 10~20Hz `A` |
| **超时** | H723 400ms 无 `Y` → 停发 `0x105`、**保持当前位置**、置故障、回 `K,5`；收到 `Y` 即恢复（`E 0` 后须 `E 1`） |
| **F103 断链** | >1s 无 `A`/`K` → `link_lost` + 停发 `Y`，**不阻塞 PID**；收到任意 `A`/`K` 即恢复（§2.5） |
| **控制权** | yaw 只由 F103 经板间串口控制；H723 调试口**不另开** yaw 命令；本地点动互斥标志本期不设 |
| **容错** | 粘包/半包/噪声/重复包头/超长/残缺包尾 全部自恢复；双方行为逐字一致（§2.2） |
| **带宽** | 115200 ≈ 11520 B/s；`Y` ~1500 + `S` ~500 + `A`/`K` ~400 B/s，**< 25%** |
