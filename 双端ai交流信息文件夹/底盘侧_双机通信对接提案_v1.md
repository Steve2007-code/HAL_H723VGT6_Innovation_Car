## 0. 一句话结论

机械臂的 **yaw 轴（达妙 4340P，CAN ID 0x05 / 回传 0x15）在电气上挂在底盘板 H723 的 FDCAN1**，
机械臂板 F103 没有直连它，所以必须由 F103 通过串口把 yaw 目标发给 H723，由 H723 代发 CAN 帧
`DM_CAN_Motor_Position_Speed()`。这是本次双机通信**唯一必须存在**的数据流。

## 2. ⚠ 先说清楚：物理归属 vs 电气归属

- 机械臂是「直角坐标」：A 轴水平（视觉 PID 跟随）、B 轴上下（只使能）、**yaw 轴旋转**。
- yaw 轴电机是达妙 **4340P，位置速度模式**，但它的 `hcan = &hfdcan1`——**和底盘 4 个 4310 在同一路 CAN1**。
- 因此：yaw 电机虽然机械上属于机械臂，**控制通道在底盘板**。F103 想转 yaw，只能「请求」H723 代发 CAN。

> 由此推出链路方向（对方文档 §6.3 只定义了状态帧，缺这一半）：
> **F103 → H723：yaw 控制帧（必须）**；H723 → F103：yaw 实际角度/底盘状态（可选，建议要）。

CAN 帧号不冲突，可放心共存：

| 用途 | 帧 ID | 长度 |
|---|---|---|
| 4×4310 速度模式 | `0x200 + ID` = 0x201~0x204 | 4B（float rad/s） |
| **4340 yaw 位置速度模式** | `0x100 + 0x05` = **0x105** | 8B（pos float + vel float，小端） |
| 使能 / 失能 | 直接发电机 ID（0x01~0x05） | 8B |
| FDCAN1 全局过滤器 | `FDCAN_ACCEPT_IN_RX_FIFO0` | 0x15 回传能进 FIFO0 |

## 3. 🚨 底盘侧当前有 3 个卡点（不修就没法联调）

这轮**只读诊断，未改任何源码**。以下 3 项需要用户授权后处理（可与通信实现一并做）。

### 3.1 工程当前编译不过（实测）

```
../Core/Src/main.c(158): error: #20: identifier "DM_Motor_4310_Yaw_ID" is undefined
Target not created. 1 Error(s)
```

`main.c` 第 158 / 165 行写的是 `DM_Motor_4310_Yaw_ID`，头文件里定义的宏是 **`DM_Motor_4340_Yaw_ID`**（0x05）。
另 4 个 4310 的使能写法是对的，只有 yaw 这一行拼错。

### 3.2 结构体「定义名」和「初始化/extern 名」不一致

| 位置 | 符号 |
|---|---|
| `DM_BLDC_Motor.c:15`（**定义**） | `DM_Motor_4310P_Yaw_StructData` |
| `DM_BLDC_Motor.c:110~128`（初始化） | `DM_Motor_4340P_Yaw_StructData` |
| `DM_BLDC_Motor.h:43`（extern） | `DM_Motor_4340P_Yaw_StructData` |
| `FourMotor_Coordination.c:28`（注释） | `DM_Motor_4340P_Yaw_StructData` |

修完 3.1 后，链接会报 `Undefined symbol DM_Motor_4340P_Yaw_StructData`。
**建议统一到 `DM_Motor_4340P_Yaw_StructData`**（与头文件 / 初始化 / 用户口头称呼一致），把 `.c:15` 的定义改掉即可。

### 3.3 4340 回传（0x15）没有解析

`Motor_UpdateData()` 的 `switch(pData[0])` 只有 0x11/0x12/0x13/0x14 四个 case，**没有 0x15**。
即：yaw 电机发了回传帧，底盘 FIFO0 收得到，但 `POS/VEL/T` 不会被填进结构体。
后果：想让 H723 给 F103 回「yaw 实际角度」就必须补这一条 case；否则只能「盲发」，无法闭环。

> 用户所说「之前还没有把 4310 电机的结构体写进来」，我理解为这第 3 条（4340 yaw 的回传解析没接）。
> 若不是，请指正。

### 3.4 4340 初始化参数现状（供对方核对量纲）

| 字段 | 值 | 字段 | 值 |
|---|---|---|---|
| `ID` | 0x05 | `BackID` | 0x15 |
| `Position_max/min` | ±12（rad） | `Velocity_max/min` | ±30（rad/s） |
| `Kp` / `Kp_max` | 20 / 500 | `Kd` / `Kd_max` | 2 / 5 |
| `Torque_max/min` | ±10 | `hcan` | `&hfdcan1` |

`DM_CAN_Motor_Position_Speed(ax, vel, pos)` 内部把 `pos` / `vel` 各打包成 4B 小端 float，
发到 `0x100+ID`。**pos 单位是 rad（绝对值），vel 单位是 rad/s**，不是角度、不是脉冲、不是微步。

## 4. 通信方案草案

### 4.1 物理层

| 项 | 建议值 |
|---|---|
| 链路 | F103 USART2 (PA2/PA3) ↔ H723 空闲 UART（**候选 USART6 PC6/PC7**，或 USART2 PA2/PA3） |
| 电平 | 3.3V TTL，**必须共地**，TX↔RX 交叉；不是 RS232/RS485 |
| 速率 | 115200 8N1（双方时钟误差：F103 PCLK1=36MHz → BRR=312，误差 +0.16%；H723 HAL 自动算） |
| 双工 | 双向：F103 发 yaw 命令 + 状态；H723 发 yaw 实际值 + 底盘状态 |
| 中断 | H723 新串口 RX 中断优先级低于 TIM4；F103 USART2=4（对方已规划） |
| 发送 | 双方都用 TXE/中断或 `HAL_UART_Transmit_IT` 非阻塞，**禁止轮询忙等**（会破坏 F103 的 10ms PID 和 H723 的 200Hz 环） |

> ⚠ 对方文档 §6.4 第 1 条：USART2 的 BRR 绝不能照抄 `vision.c`（72MHz/115200=625），
> 必须用 `(SystemCoreClock/2)/baud = 312`。底盘侧 HAL 无此坑。

### 4.2 帧格式：直接沿用 `<<...>>`

**最大公约数**：F103 的 `vision.c` 已有成熟的 `<<X,dx,Y,dy>>` 状态机解析器（含粘包/半包/噪声/重复包头容错），
H723 的 `Debug.c` 也是 `<<cmd args>>`。板间协议沿用同一套包头文件，**对方几乎零成本复用解析器**。

- 包头 `<<`，包尾 `>>`，逗号分隔字段，`\r\n` 或 `\n` 均可作行尾
- 全部 ASCII 文本，不做二进制帧（便于串口助手直接调试、也避免浮点字节序问题）
- 不加校验和（沿用用户此前决定：复杂包头 + 包尾即可）

### 4.3 命令集（草案）

**F103 → H723（下行，必须）**

| 帧 | 含义 | H723 动作 |
|---|---|---|
| `<<Y,<pos>,<vel>>` | yaw 目标：位置(rad) + 速度(rad/s) | `DM_CAN_Motor_Position_Speed(&DM_Motor_4340P_Yaw_StructData, vel, pos)` |
| `<<E,<0\|1>>` | yaw 使能 / 失能 | `DM_CAN_Motor_SetEnable(DM_Motor_4340_Yaw_ID, Enable/Disable)` |
| `<<H>>` | 心跳（若 Y 帧本身 ≥10Hz 可省） | 刷新看门狗 |

**F103 → H723（状态上报，可选，沿用对方 §6.3 骨架）**

| 帧 | 含义 |
|---|---|
| `<<S,<posA>,<posB>,<velA>,<valid>>` | 机械臂 A/B 轴位置 + 速度 + 视觉有效标志 |

> 对方 §6.3 已知缺口：`Stepper_GetSpeed()` 不带方向，`velA` 若要带符号需补 `Stepper_GetVelSigned()`。
> 底盘侧不解析 `S` 帧也能工作；若要做任务同步（例如「机械臂到位后才允许底盘开车」）再启用。

**H723 → F103（上行，建议要）**

| 帧 | 含义 | 依赖 |
|---|---|---|
| `<<A,<pos>,<vel>,<err>>` | 4340 实际位置/速度/错误码（rad / rad/s） | **依赖卡点 3.3 补 0x15 解析** |
| `<<C,<state>,<x>,<y>,<yaw>>` | 底盘状态 + 位姿（mm / deg） | 可选，用于任务协同 |
| `<<K,<cmd>>` | 命令确认 / 错误回报 | 可选 |

### 4.4 数值格式（**待拍板重点**）

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）整数定点** | `pos` 单位 **0.001 rad**（int，毫弧度），`vel` 单位 **0.001 rad/s**；H723 收到后 ×0.001f 还原 float | F103 裸机无需浮点库/sscanf，`vision.c` 的整数解析状态机可直接复用；最稳 |
| B 文本浮点 | `<<Y,1.5708,0.5000>>` | 可读性好，但 F103 需自己写 `atof`（裸机无 stdlib 或要拉大代码），且要约定小数位 |

例（方案 A）：`<<Y,1571,500>>` = 目标 1.571 rad（90°）、限速 0.500 rad/s。

**限幅建议**（H723 侧硬钳，防止 F103 发飞）：
`pos ∈ [-3142, 3142]`（±π，可按机械限位收紧）、`vel ∈ [-3000, 3000]`（±3 rad/s，远小于电机 ±30 上限）。

### 4.5 超时与安全（**强烈建议**）

| 机制 | 建议值 | 理由 |
|---|---|---|
| H723 侧 yaw 命令看门狗 | **300~500 ms** 无 `Y`/`H` 帧 → 停止下发，yaw 保持当前位置（或失能，待拍板） | 串口线松了/对方死机时，不能让 4340 一直顶着最后一条位置指令或继续转 |
| F103 侧上报周期 | 10~20 Hz（可挂在 TIM3 10ms 里，但发送非阻塞） | 与对方 PID 周期同频 |
| F103 侧收不到 `A` 帧 | 只记录，不阻塞 PID | 避免把机械臂控制卡在串口上 |
| 上电默认 | yaw **失能 / 保持**，直到收到第一条 `E 1` + `Y` | 防止上电乱转 |

> 底盘侧已有同类设计：`g_nav_manual_wd` + 800ms 看门狗、`<<v>>` 手动速度超时自动停。沿用同一理念。

### 4.6 时序与资源

```
F103 TIM3 10ms PID  ──► 组 <<Y,pos_mrad,vel_mradps>> ──USART2 100Hz──►  H723 RX 中断(仅收字节进 FIFO)
                                                                        │
                                                          H723 主循环 Link_Poll() 非阻塞解析
                                                                        │
                                                          限幅 + 看门狗 + 限流(≤100Hz)
                                                                        │
                                                    DM_CAN_Motor_Position_Speed(0x105, 8B)
                                                                        │
H723 ◄──USARTx 10~20Hz── <<A,pos,vel,err>> ◄── 4340 回传 0x15 → Motor_UpdateData 补 case
```

**三条硬约束**：

1. **CAN 发送不要放进串口 RX 中断**。FDCAN1 上已有 4×4310 以 200Hz 发速度帧（0x201~0x204）；
   yaw 帧（0x105）应放在主循环非阻塞转发，TxFifoQ 深度 8，1Mbps 下总占用约 10%，安全。
2. **H723 的解析挂主循环**（与 `Debug_Task()` 并列），不要进 TIM4 5ms 中断。
3. **控制权单一**：建议 yaw 只由 F103 通过板间串口控制，底盘调试口不另开 yaw 命令，避免双主打架。
   （若需要本地点动调试，另设互斥标志，待拍板。）

## 7. 给机械臂端 AI 的落地提示（可直接转发）

1. 请确认 `mcu_link.c` 的帧解析状态机支持 **`<<Y,<int>,<int>>`**（逗号分隔、纯整数、3 字段）；
   不支持的话把 `vision.c` 那套状态机参数化即可，别另起一套。
2. USART2 初始化：`BRR = (SystemCoreClock/2)/115200 = 312`，**不要照抄 USART1 的 625**。
3. 发送用 TXE 中断 + 环形缓冲，禁止 `while(!(SR&TXE))` 忙等；USART2 中断优先级设 4。
4. `Y` 帧建议 100 Hz（挂在 TIM3 10ms 里组包，非阻塞发送）；`S` 帧 10~20 Hz 即可。
5. 数值单位：**pos = 0.001 rad，vel = 0.001 rad/s，均为有符号整数**。请在 F103 侧也做同样限幅。
6. 若 F103 侧 vision PID 同时输出 A 轴速度，注意「yaw 目标」和「A 轴跟随」是两条独立链路，
   不要共用 `g_track_enabled` 互斥标志（那个只管 A 轴）。
7. 底盘侧 `<<...>>` 帧不加校验和，靠包头包尾防噪声拼包；请保持一致。
8. 上电默认 yaw 失能，收到 `<<E,1>>` + 首帧 `Y` 才开始动。
