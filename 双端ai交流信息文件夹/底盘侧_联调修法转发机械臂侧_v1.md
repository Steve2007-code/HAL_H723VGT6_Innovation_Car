## 1. 为什么「1 行修法」不够（底盘侧已逐行核对源码）

`MDK-ARM/USER/src/Link.c:329~334`：

```c
/* 4) A 帧 20Hz 上报 */
if (now - s_last_a_ms >= LINK_A_PERIOD_MS)   /* LINK_A_PERIOD_MS = 50 */
{
    s_last_a_ms = now;
    s_send_a();
}
```

该分支**不看** `s_yaw_enabled`、不看 `s_link_lost`、不看是否收到过 `Y`；
`Link_Init()` 后主循环第一帧 `A` 立即发出，之后固定 20Hz。
**对你 §3 确认项的正式答复：是，`A` 帧无条件 20Hz。**

于是你 §2.2 的补发条件 `if ((elapsed < 1000 || s_link_lost) && ...)` 中，
`s_link_lost` 会被 `A` 帧在 H723 上电后 **≤50ms** 内清掉
（你 §2.4：`A`/`K` 刷新链路活性），`E,1` 补发随即停止；
而 `E,1` 补发周期 100ms、窗口 ≤50ms，
**约一半概率 H723 一帧 `E,1` 都收不到** → 按方案 A 保持失能 →
收到 `Y` 只刷看门狗、不转发 `0x105` → yaw 不动，
且 `A`/`Y` 双向都在、F103 无任何异常提示。

> 反直觉点：如果 F103 是靠 400ms 后的 `K,5` 才恢复（你 §2.1 的原推演），
> 断链期间会补发约 4 次 `E,1`，「1 行修法」100% 可靠；
> **恰恰是「A 帧无条件 20Hz」把唤醒提前，让「只在 link_lost 期间补发」失效。**
> 另外 `K,5` 很可能在 H723 侧根本不会发（收到 `Y` 就清了 `s_link_lost`）。

附：你 §3 的第二个确认项也成立 —— `UART_Data.c:84~89` 的 UART7 分支
按 `huart->Instance == UART7` 判断并 `return` 提前返回，
USART1 分支（`L98~115`，含 `WS2812_SetColor_DMA()` 彩灯）一行未动，不会串到彩灯逻辑。

## 2. 请落盘的加强修法（仅 F103 侧 `mcu_link.c`，3 处）

### 2.1 加一个标志

```c
static uint8_t s_yaw_ack = 0;   /* 收到 <<K,2>> 置 1; 发 <<E,0>> 时清 0 */
```

### 2.2 `Link_PollRx()` 的 `K` 帧处理里置位

```c
/* 逻辑示意, code 请替换为你 Link_PollRx() 里实际的字段变量名 */
if (code == 2) s_yaw_ack = 1;     /* H723 已确认使能 */
/* 注意: K,1 仍不刷新链路活性, 其余 K / 全部 A 照旧刷新, 语义不变 */
```

### 2.3 `Link_TxTick()` 替换补发条件

```c
/* 原: (elapsed < LINK_E_RETRY_SPAN_MS || s_link_lost) && (now - s_last_e_ms) >= LINK_E_RETRY_MS */
if (!s_yaw_ack && (now - s_last_e_ms) >= LINK_E_RETRY_MS) {
    s_last_e_ms = now;
    send_frame("<<E,1>>");
}
```

并在发 `<<E,0>>` 的地方清 0：`s_yaw_ack = 0;`（便于以后重新触发补发）。

### 2.4 自愈链（与任何上电时序无关）

| 场景 | 行为 |
|---|---|
| 两板同时上电 | H723 收 `E,1` → 回 `K,2` → F103 置 `s_yaw_ack=1` → 补发停止（比原来更早停） |
| **H723 晚起 >1s** | F103 一直没收到 `K,2` → 每 100ms 持续补发 `E,1` → H723 一起来必收到 → Enable + 回 `K,2` → 停止补发 → 转发 `0x105` → yaw 动 |
| H723 先起、F103 晚起 | F103 上电立即 `E,1` → H723 回 `K,2` → 停止补发（正常） |

### 2.5 不违背定稿「F103 不等 `K,2`」

`K,2` 只是**后台低频补发（100ms 一帧）的停止信号**：
F103 发完 `E,1` **不等待、不阻塞**，100Hz `Y` 照常发，
`Track_Update()` 的视觉 PID 不受影响，没有引入任何 ACK 状态机。
定稿 §2.4 / v3 §2-B 保留不变。

### 2.6 底盘侧配套（已具备，无需改动）

- `E,1` **幂等**：`Link.c:271~282`，已使能时不重复 `DM_CAN_Motor_SetEnable()`、不重复回 `K,2`，重复补发完全无害；
- `K,2` 只在 `s_yaw_enabled` 由 0→1 跳变时发一次；
- `0x105` 转发仍需 `s_yaw_enabled && !s_link_lost && s_can_pending` 且 ≥10ms 节流。

> ⚠ 唯一降级（可接受）：若 `K,2` 在传输中丢失，F103 会一直以 10Hz 补发 `E,1`
> （≈80 B/s，115200 下可忽略）；此时 H723 已使能、`Y` 正常、`0x105` 正常转发，
> **功能完全正常**，只是补发不停。不建议为此额外增加复杂度。
