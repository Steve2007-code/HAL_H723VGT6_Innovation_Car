## 2. 关键实现细节（逐条对应定稿规格）

### 2.1 USART2 裸机初始化（`Link_Init`）

| 项 | 实现 |
|---|---|
| 时钟 | `RCC->APB1ENR \|= RCC_APB1ENR_USART2EN`（APB1）；`RCC->APB2ENR \|= IOPAEN \| AFIOEN` **自己置位，不依赖 `Vision_Init` 顺序** |
| 引脚 | `GPIOA->CRL`：PA2 = `0xB`（复用推挽 50MHz TX）、PA3 = `0x4`（浮空输入 RX）；**不碰 `AFIO->MAPR`**，保持默认 PA2/PA3 |
| 波特率 | `USART2->BRR = (SystemCoreClock / 2U) / 115200U = 312`（PCLK1=36MHz，**不是 625**） |
| CR1 | `UE \| TE \| RE \| RXNEIE`；`TXEIE(bit7)` 仅在有帧待发时由 `send_frame()` 打开 |
| 优先级 | `NVIC_SetPriority(USART2_IRQn, 4)` |
| 中断 | `USART2_IRQHandler`：RXNE 只 `Frame_FeedByte(&s_link, c)`；TXE 只从环形缓冲取一字节写 `DR`，缓冲空则关 TXEIE。**ISR 内无组包、无解析、无忙等** |

### 2.2 成帧与解析

- 状态机 `0=等< / 1=等第二个< / 2=收body / 3=等第二个>`，容错：重复包头 `<<<`、粘包、超长丢帧、残缺包尾、噪声。
- **两个独立实例**：`s_cam`（vision.c，USART1）/ `s_link`（mcu_link.c，USART2）；H723 侧另有 `s_link_h723`，互不共享状态。
- `parse_cmd_ints()` 返回字段数 1~4，失败返回 0；**帧内 `\r\n` 会被当普通字符塞进 body 导致解析失败**，故 F103 发送侧一律不带行尾。
- 数值走裸机 `i2s()` 整数转字符串，**不用 `sprintf`**，不引入浮点库。

### 2.3 发送与握手

- `<<E,1>>`：`Link_Init()` 末尾**立即发 1 次**，随后上电前 1s 每 100ms 补发（合计约 11 次），覆盖两板上电不同步导致 `E` 全丢。
- `<<Y,pos_mrad,vel_mradps>>`：每个 10ms tick 发一次 = **100Hz**；F103 侧先按 `±3142 / ±3000` 限幅再组包。
- 发送是**整帧原子投递**：TX 环形缓冲剩余空间不足则整帧丢弃，绝不忙等；实际字节由 TXE 中断发出。
- **不等 `<<K,2>>`**：发完 `E,1` 直接进 100Hz `Y`，`K,2` 只作状态记录。

### 2.4 接收与断链

- `<<A,pos,vel,err>>`：`pos/vel/err` **只存不解释**（`err` 为 MIT 回传原始字节）。
- `<<K,code>>`：只存；**`K,1`（上电就绪）不刷新链路活性**，其余 `K` 与全部 `A` 刷新。
- `link_lost`：`>1s` 无 `A`/`K` → 置位并**停发 `Y`**；收到任意 `A`/`K` 即自动恢复。**绝不阻塞 `Track_Update()` 的 PID**。
- 单向断链（F103→H723 断）：仍能收到 H723 的 `A`，`link_lost` 不会置位，**继续发 `Y` 是自愈所需**，安全由 H723 400ms 看门狗兜底（已在源码注释写明）。

### 2.5 主循环顺序（`main.c`）

```c
if (g_tick_10ms) {
    g_tick_10ms = 0;
    Link_PollRx();      /* 1) 先收 A/K */
    Track_Update();     /* 2) 视觉 PID + 下发 A 轴速度，不发帧 */
    Link_TxTick();      /* 3)+4) 取 yaw 目标 + 组包投递 TX 缓冲 */
}
```

> 1. **API 名差异**：我方把主循环链路拆成 **`Link_PollRx()`（收）** 与 **`Link_TxTick()`（发）** 两个函数，
