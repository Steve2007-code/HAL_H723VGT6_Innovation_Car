## 2. 🚨 新边界：H723 重启后 yaw 永久失能（必须修）

### 2.1 推演

`s_yaw_ack` 目前**只有一个置 1 的地方（`K,2`），没有任何清 0 的地方**（`E,0` 路径本期未实现）。

| 时刻 | H723 | F103 |
|---|---|---|
| 首次上电 | `s_yaw_enabled=0`，发 `K,1` | 发 `E,1` → 收 `K,2` → **`s_yaw_ack=1`**，停补发，100Hz `Y` |
| 正常运行 | 转发 `0x105`，yaw 正常 | 正常 |
| **H723 被复位**（按键/掉电/看门狗/重烧） | `Link_Init()` 重跑：**`s_yaw_enabled=0`**（方案 A 上电失能），发 `K,1`；`A` 帧继续 20Hz | 收到 `K,1`（**不刷新活性**，L162）+ 持续收到 `A`（刷新活性）→ `link_lost` 不置位 |
| 之后 | 等 `E,1`，永远等不到 | **`s_yaw_ack` 仍为 1 → 永不补发 `E,1`** |
| 结果 | **yaw 永久失能**；收到 `Y` 只刷看门狗、不转发 `0x105` | 链路看起来完全正常（`A`/`Y` 双向都有），**无任何异常提示** |

> 比原边界更隐蔽：原边界至少 F103 处于 `link_lost` 状态，这次连 `link_lost` 都是 0。

### 2.2 修法（F103 侧 1 行）

`Link_PollRx()` 的 `K` 帧分支（`mcu_link.c` L157~162）：

```c
} else if (cmd == 'K' && n >= 1) {
    s_k_code = (uint8_t)v[0];
    if (s_k_code == LINK_K_ENABLED) s_yaw_ack = 1;
    if (s_k_code == LINK_K_READY)   s_yaw_ack = 0;   /* 新增: H723 重新上电, 使能状态已丢 */
    if (s_k_code != LINK_K_READY) s_last_rx_ms = g_ms;
}
```

- **为什么精准**：`K,1` 在 H723 侧只在 `Link_Init()` 发一次（不周期发），语义就是「我刚上电、我的一切状态都丢了」，正好用来重置握手状态；
- **为什么安全**：`K,1` 不刷新链路活性（既有语义不变），清 0 后 F103 立即恢复每 100ms 补发 `E,1` → H723 收到 → Enable → 回 `K,2` → 置 1 → 停补发，闭环自愈；
- **底盘侧零改动**，协议/帧集不变。

### 2.3 建议（非必须）

`Link_Init()` 里建议显式写一行 `s_yaw_ack = 0;`（与 `s_link_lost = 0;` 等并列）。静态变量初值已是 0，功能上非必须，但能表达意图、防止将来改 no-init 段时踩坑。

## 3. 极角闭环复核

### 3.1 `atan2_mrad` 精度（✅ 与回执一致）

我用 Python 逐位复现该定点实现，扫 `dx,dy ∈ [-300,300]` 步长 3：

| 项 | 实测 |
|---|---|
| 全象限最大误差 | **4.71 mrad @(dx,dy)=(-147,-225)**，回执称 4.7 mrad ✅ |
| 正上 `(0,-100)` | 0（ref 0.0）✅ |
| 正右 `(100,0)` | 1571（ref 1570.8）✅ |
| 正下 `(0,100)` | 3142（ref 3141.6）✅ |
| 正左 `(-100,0)` | -1571（ref -1570.8）✅ |
| 左上/右上 45° | ∓785（ref ∓785.4）✅ |

防除零（`ax==0` 必走 `ay>ax` 分支）、防溢出（`v*t ≤ 32768×34682 ≈ 1.14e9`、`a*3142 ≤ 3.24e8`，均在 int32 内）**均正确**。

### 3.2 ⚠️ Q12 截断让死区翻倍（实际影响最大的问题）

`d = (s_phi_f * YAW_KP_Q12) >> 12`，KP=41 时：

| `phi_f` | `d` | 结果 |
|---:|---:|---|
| 99 | 0 | **目标角不再变化 → 永久卡住** |
| 100 | 1 | 每次 1 mrad/tick |
| 3142 | 31 | 正常 |

**理论最小残差 = 4096/KP = 99.9 mrad（5.72°）**，大于 `YAW_ANGLE_DEAD=50`，所以：
- 实际有效死区 ≈ 99.9 mrad，配置的 50 mrad **完全被覆盖、调它没有效果**；
- yaw 会稳定在距目标 **5~6°** 的位置，A 轴（像素 PID）补不上这个角度偏差，抓取会歪。

闭环数值仿真（`phi0=1000`，4340 限速 0.5 rad/s）末态：

| KP（Q12） | 理论最小残差 | 仿真末态 `phi` | 最大超前 |
|---:|---:|---:|---:|
| **41（当前）** | 99.9 mrad / 5.7° | **97 mrad** | 197 mrad |
| 100 | 41.0 mrad / 2.35° | 0 mrad | 1412 mrad |
| 200 | 20.5 mrad / 1.17° | 0 mrad | **2221 mrad（瞬时饱和到 ±3142）** |

**推荐修法（二选一，或叠加）**：

```c
/* 方案 A: 截断补偿——保持 KP 不变, 只在被截成 0 时给最小步长 */
d = (s_phi_f * YAW_KP_Q12) >> 12;
if (d == 0 && s_phi_f != 0) d = (s_phi_f > 0) ? 1 : -1;

/* 方案 B: 直接把 KP 从 41 提到 60~100 */
```

> 推荐 **方案 A**：不改变增益/收敛速度特性，只消除截断，能让 yaw 真正走进 50 mrad 死区。
> 方案 B 见效快但会放大超前（KP=200 实测瞬时撞 ±3142 限幅），必须同时把 RATE 限幅压下来。

### 3.3 ⚠️ 速率不匹配（会过冲，但不会发散）

| 宏 | 值 | 折算 |
|---|---:|---|
| `YAW_RATE_MAX_MRAD` | 20 mrad/10ms | **2 rad/s**（目标角最大变化率） |
| `YAW_VEL_MRADPS` | 500 mrad/s | **0.5 rad/s**（4340 位置环限速） |

目标角最多以 2 rad/s 涨、执行器只能 0.5 rad/s 追 → 目标持续超前。仿真最大超前 **197 mrad（11°）**，之后追上（因为 `phi` 随实际转动而减小，`d` 自限，**不会累积到饱和**）。

不过起始角接近 ±π 时会瞬时撞限位：

| 起始 `phi0` | 首次撞 ±3142 | 末态 |
|---|---:|---|
| 1000 mrad | 无 | 903（收敛） |
| 3000 mrad（近正下方） | **tick 157 → 1.57s 撞限位** | 2950（回落收敛） |
| -3141 mrad | **tick 157 撞限位** | -3142（贴限位） |

**建议**：`YAW_RATE_MAX_MRAD` 20 → **5**（= 0.5 rad/s，与 `YAW_VEL_MRADPS` 精确对齐），超前从 197 mrad 降到 **0**，且不需要改底盘侧。联调确认方向和增益稳定后，再把两者一起提高（例如 RATE=10 / VEL=1000）。
