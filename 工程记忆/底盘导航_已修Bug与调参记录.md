## 1. 🔴 `s_yaw_t` 初始航向算错 → 到点狂转（最隐蔽的坑）

**现象**（2026-11-21 实测）：

```
# WP total=3  pose=(1212,2155) yaw=-179.9
   [0] (1225,2175)      ← 这是"当前所在格心"，离车 24mm
   [1] (1205,2175)  seg=+180
   [2] (1205,285)   seg=-90
```

车原地转了 **247° 再反向转回来**，然后才开始走。每个航点都这样。

**根因**：

```c
/* s_commit() 里的原代码 */
s_yaw_t = s_seg_yaw(g_pose.x, g_pose.y, s_wpx[0], s_wpy[0]);
```

而 `s_wpx[0]` 是 `s_build_from_cells()` 填的**起始格心**，不是车的实际位置。
于是初始航向被算成"车 → 格心"的**斜角**：

```
车 (1212,2155) → 格心 (1225,2175)：atan2(20,13) = 57°
车实际朝 -180° → 误差 237° → 原地狂转
```

**更致命的是**：`Nav_Update()` 里**转向判据在前、到点判据在后**：

```c
if (fabsf(yaw_err) > NAV_TURN_GATE) { 原地转; return; }   // ← 先
...
if (d < 到达判据) { s_wp_next(); }                        // ← 后
```

航向错了就永远卡在转向分支，**转不到 25° 以内就永远不推进航点**，所以转不完。

**修法**（`s_build_from_cells` + `s_commit`）：

1. `s_px[0]/s_py[0]` 改成 `g_pose.x/y` —— 首点用**真实位姿**，不用格心
2. `s_commit` 里若首点就在脚下（≤40mm），**直接跳到第二点**，用第一段的真实方向定航向：

```c
if (s_wpn >= 2) {
    float d0x = s_wpx[0] - g_pose.x, d0y = s_wpy[0] - g_pose.y;
    if (d0x*d0x + d0y*d0y < 1600.0f) {   /* <40mm */
        s_wpi = 1;
        s_yaw_t = s_seg_yaw(s_wpx[0], s_wpy[0], s_wpx[1], s_wpy[1]);
    }
}
```

**验证**：改后 WP 打印首点变成实际坐标，每个航点只转一次 90°，跑完 15 点路线无一次异常旋转。

## 2. 🟡 `Nav_PlanToMm` 事后插 L 拐角 → 20mm 倒退段

**现象**：到点时先倒退 20mm 再拐弯，表现为"到了又退回去"。

**根因**：旧实现是"先按格心规划完，再把最后一个航点改成精确 mm，并补一个 L 拐角"：

```c
/* 旧代码 */
s_wpx[last] = x_mm;  s_wpy[last] = y_mm;
if (ax != 0 && ay != 0) {   /* 变斜段了, 补拐角 */
    c1 = (x0, y_mm);  c2 = (x_mm, y0);
    ...
}
```

若精确点在**来向的后方**，这个 L 会造出反向小段。例：

```
[1] (2275,725)  ↑上
[2] (2275,705)  ↓下   ← 20mm 倒退，逼车原地掉头 180°
[3] (2195,705)  ←左
```

**修法**：把精确终点**提前**到正交化之前，让 `s_ortho()` 自然处理：

```c
/* Nav_PlanToMm 现在 */
s_goal_x = x_mm;  s_goal_y = y_mm;  s_goal_exact = 1;
ok = s_plan_cells(r, c);
s_goal_exact = 0;
```

```c
/* s_build_from_cells 里 */
if (s_goal_exact && n > 1) {
    s_px[n-1] = (int16_t)s_goal_x;   /* 用精确 mm 取代最后一个格心 */
    s_py[n-1] = (int16_t)s_goal_y;
}
```

为支持这个，把 `Nav_PlanToCell` 拆成了内部 `s_plan_cells()` + 公开包装（包装里清 `s_goal_exact`）。

**教训**：**航点表要在生成阶段就完整，不要生成完再"打补丁"**。补丁永远不知道上游的上下文（来向、当前朝向）。

## 3. 🟡 精确终点与格心差 20mm → 碎腿

`s_ortho()` 会把"起点→精确终点"的细微偏差拆成一条 3~20mm 的小腿，多一次 90° 转向。

**修法**：新增 `s_drop_short(25.0f)`，正交化后去掉与前一点距离 < 25mm 的中间点（首尾保留）。

```c
s_ortho();
s_drop_short(25.0f);
s_merge_collinear();
```

## 4. 🟡 每个航点都白停一次

**现象**：每段之间车速降到 0 再重新加速，15 段多花 15~20 秒。

**根因**：

```c
if (d < 到达判据) {
    s_wp_next();
    Chassis_SetBodyVel(0.0f, 0.0f, wz);   /* ← 把速度清零了 */
    return;
}
```

**修法**：中间点推进时**不清零速度**，只推进航点，下一周期（5ms 后）自然按新段重算：

```c
if (d < 到达判据) {
    s_wp_next();     /* 不停车通过 */
    return;
}
```

终点不用管：`s_wp_next()` 在走完最后一点时会自己 `Chassis_Hold()`。

> 若新段需要转向，下一周期会进入转向分支把 vx/vy 清零，等于自然停车转身 —— 行为仍是安全的。

## 5. 🔴 IMU 大电流掉电 → 卡零输出（软件兜底，根因在硬件）

详细现象与诊断方法见主文档 §10.7f，这里只记结论：

- **触发**：四轮同时最大出力（原地转向）瞬间电流峰值 → 电压跌落 → IMU 复位
- **表现**：帧照常回（`gyro` 计数在涨），但三轴原始值恒为 `0x7FFF`（编码中点），欧拉角也全 0
- **后果**：`g_att.yaw` 永久冻结 → 航向环永远达不到目标 → **车无限原地转**
- **恢复**：**必须断电**，按复位键无效

**软件保护**（`Attitude.c` / `Nav.c`）：

| 保护 | 判据 | 动作 |
|---|---|---|
| IMU 失效检测 | 三轴恒 `0x7FFF` 持续 1s，或 0.5s 无新帧 | `g_imu_dead = 1`（锁存，需重启） |
| IMU 失效停车 | `RUN/ALIGN` 态下 `g_imu_dead` | 立即 `NAV_FAIL` + 停车 |
| 转向超时 | 4s 转不到位 | `NAV_FAIL`（`why=2`） |
| 转向限速 | 原地转向 wz 限幅 | 降电流峰值 + 防打滑 |

**失败原因码**（`g_nav_fail_why`，串口 `# route FAIL at N why=X`）：

```
1 = IMU 失效     2 = 转向超时     3 = A* 规划失败     4 = 起点/终点不可规划
```

**硬件上要做的**：IMU 单独供电、电源脚并 100µF + 0.1µF、检查电池放电能力。

## 6. 🟢 到点总差 7.5mm（系统性欠走）

15 个点实测误差**全部是 7.4~7.5mm，方向一律是"行进方向欠走"**：

| # | 目标 | 实到 | 误差 |
|---|---|---|---|
| 1 | 2195,705 | 2202,704 | +7.4, −1.0 |
| 5 | 1205,285 | 1205,292 | +0.2, +7.4 |
| 8 | 305,2155 | 305,2147 | 0, −7.5 |
| 13 | 2195,1205 | 2187,1205 | −7.5, −0.1 |

**根因**：`NAV_FINAL_MM = 8.0f`。车减速到剩 7.5mm、速度 0.02m/s 时正好掉进 8mm 判据 → 停车。

**修法**：`NAV_FINAL_MM` **8 → 5**（`Nav.h`）。

> 若改成 5 后出现"在 5mm 处推不动、一直蹭"，说明静摩擦太大，退回 6~7 或提高位置环 kp。

## 7. 🟢 扫码区为 50mm 横移白转 90°

`(2275,1225) → (2325,1225)` 只有 50mm，却要原地转 90°。而扫码摄像头装在车右侧，**根本不需要车头朝右**。

**修法**：末段 ≤ `NAV_SHORT_MM`(200mm) 时**锁定进入时的车头，纯平移**：

```c
if (s_wpi + 1 >= s_wpn) {
    float lx = ..., ly = ...;
    if (lx*lx + ly*ly <= NAV_SHORT_MM*NAV_SHORT_MM)
        s_yaw_t = g_pose.yaw;      /* 锁车头, 横移 */
    else
        s_yaw_t = s_seg_yaw(...);
}
```

另有 `g_force_strafe` 标志可**强制**某段横移（内置路线表里 `s_route_s[]` 逐点设置）。

> 长段不要横移：侧向长时间走麦轮打滑大，里程计会漂。
